Private workspace User guide

User guide

Your master documents

The Resume tab holds both masters — the resume, and the cover letter underneath it. Both are read-only and shown exactly as they print. Each has its own PDF button.

They change in one direction only: you write against a real posting in Fit Score, then promote a version up. Nothing an agent writes lands here on its own — thirty applications should not slowly erode what you actually wrote.

Keywords

Every resume entry carries two lists: the job titles it is evidence for, and the skills it demonstrates. These are what the agent matches a posting against. An untagged entry is invisible to it.

✦ Tag keywords fills both with AI. It only touches entries that have none, so running it again is safe. It saves for you when it finishes.

The postings list

Across the top of the Resume tab, one row per application — it stays one line tall however many you have. It carries the same columns as Job Postings: company, job title, status, posting, deadline, sent, contact, notes and what has been built.

It is read-only. It is here so you can see where every application stands while you look at your masters; Job Postings is the one place you change any of it, so there is never a question of which copy of a row you typed into.

Built links still work — they open that application's resume or cover letter ready to print, with a chip for how many versions exist. Rows for applications you have not marked complete are dimmed.

Job Postings

Every posting on one row, every field its own column — company, job title, status, how much of the description you actually have, deadline, sent date, contact, notes, and what has been built. Click a row to open it in full underneath.

Editing in the row

Deadline, Sent and Contact email are yours to type into right in the row. Notes shows a one-line preview — click it and a full-size, scrollable box opens, so an interview log or an email trail fits. Everything saves as you type. Clicking anywhere else on the row opens that posting below.

Removing applications

Each row starts with a checkbox, and the one in the header selects or deselects every row at once. Remove, at the top of the box, counts what you have ticked and hides those applications on click.

It is the same soft delete as the Delete button on an open posting: the data stays in your repo. Tick show deleted and they come straight back.

Posting tells you whether you have the real description or only an alert teaser. Nothing can be generated from a teaser.

Adding a posting

Add posting for a blank one, or One-click capture to grab it from a job page with a bookmarklet — see Capture below.

Generating

Generate resume + letter reads the posting, picks entries from your master by keyword, writes a tailored summary, and drafts the letter. It writes only into this application.

Statuses, and what freezing means

Three statuses on the application, and again on the resume and the letter: draft, complete, deleted.

  • Draft stays live — edits to your masters flow through
  • Complete freezes the text. That frozen copy is the record of what the employer received, and editing your master afterwards cannot change it
  • Deleted hides it. The data stays in your repo; tick show deleted to bring it back
Moving a completed document back to draft asks first, because it discards the record of what you sent.

Fit score

The Application box holds three columns: the posting on the left, then the resume and the cover letter written against it, so you can read a requirement and its answer without scrolling between them. The posting's heading is the picker — changing it switches every column to that application. Show opens the description for editing; edits save to that application.

Every requirement in the posting is scored twice — once against the resume, once against the cover letter — because they fail in different ways. A resume can cover something the letter never mentions.

  • Copy fix on the resume side hands you the suggestion. There is no single unambiguous place to apply it, so it does not guess.
  • Add to letter appends the suggestion to this application's letter as a draft paragraph for you to rewrite.
A zero with "no evidence" is the honest answer, not a failure of the scorer. If the posting wants something you have never done, no wording fixes that — and the fix will say so rather than help you claim it.

Every run is saved to the score history, so you can see whether a rewrite actually moved the number.

One-click capture

Grabs a posting from the page you are looking at, with no copy-paste.

  1. Show your bookmarks bar: Ctrl + Shift + B
  2. Archive tab → One-click capture
  3. Drag the green button up onto your bookmarks bar — do not click it here
  4. Open any job posting and click the bookmark. It arrives as a new application.

It reads the page your browser already loaded and passes the text in the URL fragment, which never reaches any server. Nothing is scraped, which is why it works on sites that block automated fetching.

When something breaks

"Your data repo is not connected"Environment variables missing. Vercel → Deployments → ⋯ → Redeploy.
"GitHub rejected the token (401)"Token expired — they last a year. Make a new one, update GITHUB_DATA_TOKEN, redeploy.
"lacks Contents: Read and write"Token permission. Edit it → Repository permissions → Contents → Read and write.
"Changed somewhere else"Two tabs open. Reload the one you care about least, then redo the edit.
"No Anthropic API key"Only the AI buttons need it. Add ANTHROPIC_API_KEY in Vercel and redeploy.
Bounced to loginSession expired. Normal — sign in again.

Anything not on this list, or an error that doesn't name its own fix: send me the exact wording.
